Switched to `gemini-flash-latest` instead, Google's alias for "whatever the current stable Flash model is" (currently resolves to `gemini-3.7-flash`) — this also means the *next* time Google retires a model id, the app won't silently break again the way it did this time. It retries up to 3 attempts on 429/503, with backoff, matching Google's own "usually temporary, try again" guidance. Also found and fixed a second failure mode while testing this: some attempts don't error at all, they just never respond — the same silent-hang behavior seen with `gemini-3.6-flash` earlier can happen intermittently even on `gemini-flash-latest` during high load. Added a 12s per-attempt `AbortController` timeout so a hung attempt gets cut short and retried instead of blocking forever. Re-tested AI Assist 3 times back-to-back: a normal case resolved in ~4s with real, on-topic AI-generated suggestions shown in the review panel; a congested case still failed but cleanly in ~11s with the proper error banner (previously: immediate failure with no retry at all); a fully-congested case where all 3 attempts got throttled took the full ~40s worst case before giving up — bounded now, not infinite, but still a long wait if Gemini is having a bad moment. Considered tightening the timeout further but 12s is a reasonable floor for a real structured-JSON generation call; a shorter timeout risks aborting genuinely-in-progress responses. |

| 9 | Auth flow | `frontend/src/store/authStore.ts:74-80` | `logout()` fires `api.post('/auth/logout')` before the following `localStorage.removeItem('token')` line, intending the request to carry a valid token.
